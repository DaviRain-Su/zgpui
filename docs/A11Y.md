# Accessibility snapshot contract

This document specifies how zgpui turns per-frame element semantics into the
snapshot sent to a native accessibility backend. It complements
`ARCHITECTURE.md`; the public data types remain in `src/a11y.zig`.

## Scope

The current milestone covers semantic nodes, parent/child relationships,
frame-local accessible-name resolution, modal isolation, focus mirroring, hit
testing, press actions, slider increment/decrement, text caret/selection
snapshot fields, AX set-value, selected-text / range setters, AppKit
selected/expanded/subrole state exposure, and live-region announcements.
AppKit also exposes semantic custom rotors for headings, links, images, lists,
and text inputs, plus author-defined custom rotor groups (`rotor_group`) and
sibling/tab `nav_order` overrides. Headings may carry `heading_level` (1..6 →
AppKit `accessibilityLevel`); any node may carry `description` (→
`accessibilityHelp`).

## Data and lifetime

`a11y.Node` is rebuilt during prepaint and contains:

- `id: ElementId` — stable identity used for focus and action routing
- `role: Role` — platform-neutral semantic role
- `name: NameSource`, optional inverse `label_for: ?ElementId`, and
  `value_text: ?[]const u8`
- optional `checked`, `selected`, and `expanded` state plus `disabled`
- `live: ?LivePriority` — `polite` or `assertive`; null disables announcements
- `rotor_group: ?[]const u8` — author custom rotor label; shared labels share one rotor
- `nav_order: ?i32` — sibling / Tab order override (lower first; null after numbered)
- `heading_level: ?u8` — 1..6 for `.heading` (AppKit `accessibilityLevel`)
- `description: ?[]const u8` — help text (AppKit `accessibilityHelp`)
- `placeholder: ?[]const u8` — empty-field hint (AppKit `accessibilityPlaceholderValue`)
- `value_description: ?[]const u8` — spoken value (AppKit `accessibilityValueDescription`)
- `orientation: ?Orientation` — axis for sliders / tab lists (AppKit
  `accessibilityOrientation`: Unknown / Vertical / Horizontal)
- `url: ?[]const u8` — link destination (AppKit `accessibilityURL`); from
  `Div.withHref` / Link `href`
- `identifier: ?[]const u8` — author id string (AppKit `accessibilityIdentifier`);
  from `Div.withId` when a role is registered
- `busy: bool` — loading / waiting (AppKit `isAccessibilityBusy`)
- `required: bool` — required form control (AppKit `isAccessibilityRequired`)
- `invalid: bool` — validation failure (AppKit `AXInvalid` `"true"`/`"false"`;
  status changes post `AXInvalidStatusChanged`)
- `modal: bool` — modal surface (AppKit `isAccessibilityModal`); dialog /
  sheet / drawer / modal command palette set this
- `pressable: bool` — a concrete click handler exists in this frame
- `adjustable: bool` — concrete increment/decrement handling exists this frame
- `editable: bool` — AX may replace the value (enabled text roles with an editor)
- `caret`, `selection_start`, `selection_end` — UTF-8 offsets for text roles
- `numeric_value`, `min_value`, `max_value` — slider / meter range state
- `parent_id: ?ElementId` — nearest semantic ancestor in the same frame
- `bounds: Bounds(Pixels)` — logical pixels with a top-left origin

String slices and node slices are frame-scoped. A platform backend must copy
anything it retains; `syncAccessibility` is synchronous.

## Live-region contract

Live-region text is the first non-empty value of `value_text` and the resolved
accessible name. The platform compares visible snapshots by stable `id` and
announces when a live node first appears, its chosen text changes, or its
priority changes. It does not announce unchanged nodes, empty text, removal,
or nodes excluded by modal isolation. Reappearing after modal isolation counts
as appearing again.

AppKit maps `polite` to priority `10` and `assertive` to `90`, then posts
`AXAnnouncementRequested` on the shared `NSApplication`. The user-info
dictionary contains `AXAnnouncementKey: NSString` and `AXPriorityKey: NSNumber`.

## Semantic rotor contract

AppKit exposes a rotor only when the visible composed snapshot contains at
least one matching node. Heading, link, image, and list rotors match their
same-named semantic roles; the text-field rotor matches textbox, textarea, and
search roles. Candidate order is composed document order, so modal isolation
also applies to rotor results.

Author-defined groups use `rotor_group` labels. Each distinct non-empty label
becomes an AppKit custom rotor (`initWithLabel:`) after the semantic rotors,
in first-seen document order (capped at 32 labels). Search matches nodes with
that exact label using the same forward/backward and filter rules as semantic
rotors. A node may appear in both a semantic rotor (by role) and an author
group.

Forward search begins at the first candidate when there is no current item and
otherwise starts after it. Backward search mirrors that behavior from the end.
Search does not wrap. A non-empty filter performs an ASCII-case-insensitive
substring match against the resolved accessible name, falling back to the
text value. Results target the current snapshot's AX proxy and retain the
stable element id separately so a subsequent search can resume after proxies
are rebuilt by a newer frame.

## Navigation order

`nav_order` reorders accessibility children among siblings (and among roots)
and Tab focus among focusables. Explicit values sort ascending; nodes without
an order keep relative document / registration order after numbered siblings.
Div exposes `.a11yNavOrder(n)` (also applied to its focusable entry),
`.a11yHeadingLevel(n)`, `.a11yDescription("…")`, `.a11yPlaceholder("…")`,
`.a11yValueDescription("…")`, `.a11yOrientation(.horizontal|.vertical)`,
`.a11yBusy` / `.a11yRequired` / `.a11yInvalid` / `.a11yModal`, and
`.a11yRotorGroup("Label")`.
`field.applyValidationA11y` / `field.control` set `invalid` and map
`error_message` to `description`; `field.errorMessage` is an assertive live
label while invalid. TextInput / TextArea publish `placeholder` from their
props; Slider publishes a percent `value_description` and horizontal
`orientation`; Progress / Meter publish numeric range + percent
`value_description` (indeterminate progress uses `busy`); tab lists publish
horizontal `orientation`. Link `href` publishes `url` for AppKit
`accessibilityURL`. Separator publishes `.separator` + orientation.
Radio lists publish `.radio_group` (AppKit `AXRadioGroup`) with horizontal
orientation; options keep `.radio` + checked. `withId` names publish as
`identifier` / AppKit `accessibilityIdentifier`. Avatar publishes `.img`
(optional `a11y_label`). Scrollbars publish `.scrollbar` + orientation +
numeric offset range. Collapsible / accordion triggers expose `.button` +
`expanded`. Modal dialog, sheet,
drawer, and command-palette panels set `modal`. Menu / select / combobox /
popover triggers set `expanded`; open menu lists are modal + expanded;
popover panels use `.dialog` + modal. AppKit exposes `AXShowMenu` for
expandable pressables. Select triggers use `.pop_up_button`; combobox
triggers use `.combobox`; open option lists are modal + expanded.

## Accessible names

Names resolve only against the node's original frame:

1. An explicit `.label` wins.
2. `.labelled_by` follows the referenced node recursively.
3. A node with no explicit name may be named by the first resolvable
   document-order node whose `label_for` targets it. `Label.for_id` creates
   this inverse relation.
4. Missing targets, self-references, and reference cycles resolve to no name.

The resolver is allocation-free and bounded by the frame's node count. Before
frames are combined, snapshot composition materializes each resolved name as a
direct `.label` and clears `label_for`. This prevents a hidden main-frame label
or an unrelated overlay with a colliding id from naming a visible modal node.

## Snapshot composition

The main frame and every built overlay own separate `FrameState.a11y` lists.
Before native sync, `OverlayStack.appendAccessibilityNodes` composes one
ordered snapshot:

1. With no modal overlay, append the main frame, then overlays from lowest to
   highest `z_index`.
2. With one or more modal overlays, omit the main frame and every layer below
   the topmost modal; append that modal and any layers above it.
3. Resolve and materialize names within each source frame before appending it.
4. Preserve document order inside each frame. Do not rewrite `parent_id`.

AppKit then diffs the composed snapshot against the previous store by stable
`ElementId`: matching nodes keep their AX proxy objects, and
`AXLayoutChanged` is posted only when identity, role, parent, document order,
or `nav_order` changes. Value / caret / selection updates still emit the
existing state notifications without rebuilding the proxy tree.

This makes a modal dialog the accessible root surface while still allowing a
non-modal tooltip or toast above it to be announced.

## Actions

Native actions route back to the live source frame rather than mutating the
snapshot. Press requires an enabled `pressable` node. Increment/decrement
require an enabled `.slider` node marked `adjustable`; they reuse the slider's
keyboard step, clamping, controlled/uncontrolled, and `on_change` behavior.
Set-value requires an enabled text role marked `editable`; it focuses the
control, selects all, and inserts (or deletes when empty) through the same
keyboard / text-input handlers as typing. Replace-selected-text inserts at
the caret or replaces the active selection; set-selected-range updates the
UTF-8 caret/selection through a dedicated focus handler (AppKit converts
NSRange UTF-16 units at the bridge). All actions search visible overlays
topmost-first and cannot reach main content or lower layers hidden by a modal.

## Interface and errors

```zig
pub fn appendAccessibilityNodes(
    self: *const OverlayStack,
    main_nodes: []const a11y.Node,
    out: *std.ArrayList(a11y.Node),
    allocator: std.mem.Allocator,
) error{OutOfMemory}!void
```

The function appends to `out`; callers may pre-populate it. It performs no
platform calls and has no side effects on overlay state.

## Test specification

- Happy path: main nodes precede a non-modal overlay node.
- Modal path: the topmost modal hides main and lower-overlay nodes.
- Stacking path: non-modal layers above the topmost modal remain present.
- Empty path: empty main and empty overlays produce no nodes.
- Hierarchy path: a child's `parent_id` survives snapshot composition.
- Name path: chained and inverse label references resolve within one frame;
  missing and cyclic references resolve to none.
- Isolation path: a name reference never resolves through another frame or a
  layer hidden by a modal.
- Dialog path: an open dialog exposes a `.dialog` panel node with `modal`
  true (AppKit `isAccessibilityModal`).
- Menu path: open menus expose `.menu` / `.menu_item` with modal + expanded;
  triggers and menubar items expose `expanded`; AppKit offers `AXShowMenu`.
- Popover path: open popovers expose a modal `.dialog` panel; triggers expose
  `expanded`.
- Action path: native press dispatch checks visible overlays topmost-first and
  never reaches content hidden by a modal.
- Adjust path: slider increment/decrement uses the same step as arrow keys,
  while disabled, missing, and modal-hidden targets reject the action.
- State path: switch, search, dialog, tab, and outline-row roles expose their
  AppKit subroles; `selected` and `expanded` use the protocol's `isAccessibility*`
  getters, and checked/selected/expanded transitions emit matching native
  notifications.
- Live path: a visible live node announces once on insertion and again only
  when its selected text or priority changes; toast messages default to polite.
- Rotor path: AppKit exposes only semantic rotor categories present in the
  visible snapshot; forward/backward searches preserve document order, honor
  name/value filters, stop at boundaries, survive AX proxy rebuilds, and never
  include modal-hidden nodes.
- Text path: textbox/textarea nodes expose caret and selection UTF-8 offsets;
  `selectedText` returns the selected substring when a range is active;
  set-value replaces contents through select-all + insert/delete;
  set-selected-range converts exact AppKit UTF-16 boundaries to internal UTF-8
  offsets, ends active composition, and replace-selected-text edits at that
  caret/selection.
- Invalid text-range path: reversed, out-of-bounds, overflowed, UTF-8
  continuation-byte, and UTF-16 mid-surrogate ranges are rejected without
  changing focus, composition, caret, or selection.

## Boundary conditions

1. No main nodes and no overlays.
2. An overlay with no semantic nodes.
3. Multiple non-modal overlays.
4. Multiple modal overlays; only the highest modal starts the snapshot.
5. Non-modal overlays above a modal.
6. Non-modal overlays below a modal.
7. Equal `z_index` layers after the stack's deterministic id sort.
8. Duplicate element ids across independent layers (preserved as supplied,
   but never used for cross-frame name resolution).
9. A focused id omitted by modal isolation (native focus resolves to none).
10. Parent ids never cross frame or overlay boundaries.
11. Disabled nodes remain visible but expose no press or adjust action.
12. Allocation failure aborts the frame before native sync.
13. AX text setters reject missing, disabled, non-editable, and modal-hidden
    targets without dispatching an editor mutation.
14. Nodes without optional selected/expanded state return false, and roles
    without an AppKit subrole return none.
15. Live nodes with neither a non-empty value nor resolved name are silent.
16. Multiple new live nodes announce in composed paint order.
17. A live node removed from the snapshot emits no announcement.
18. A live node hidden below the topmost modal emits no announcement.
19. Rotor search with no current item starts at the directional edge.
20. Rotor search from the first/last matching item does not wrap.
21. Rotor filtering excludes unnamed and nonmatching candidates.
22. A current rotor result resumes from the same stable element id after the
    platform rebuilds AX proxies for a newer snapshot.
